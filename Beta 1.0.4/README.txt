================================================================================
  DIT OFFLOADER  v1.0.4  —  数字影像工程素材备份与校验工具
================================================================================

  适用场景：影视片场的 DIT（数字影像工程）工作流程 ——
  将摄影机存储卡中的原始媒体素材（MXF, MOV, R3D, BRAW 等）
  安全备份到目标硬盘，并对每份文件进行 XXHash-64 校验，
  生成可视化 HTML 场记报告。


【主要功能】

  ● 素材拷贝 —— 并行多线程，支持断点续传和多种重名策略
  ● XXHash-64 校验 —— C 扩展实现，比 MD5 快数倍
  ● 场记重命名 —— 导入 SSCL 场记板 XML，自动按场/镜/次/机位
    重命名媒体文件及附属 XML
  ● HTML 报告 —— 视频缩略图 + 元数据 + 校验值 + 文件清单
  ● 微信推送 —— 任务完成/失败/中断后通过 pushplus 推送到微信
  ● 深色界面 —— 三栏布局，支持拖拽添加源路径


【系统要求】

  Windows 10/11 (64-bit)
  macOS 13+ (Intel / Apple Silicon)

  无需预装 Python 或任何依赖。


【使用方法】

  1. 启动 DIT OFFLOADER
  2. 左侧面板浏览驱动器，拖拽或双击添加源文件夹
  3. 中间面板设置目标路径、作业名称、重名策略
  4. 可选：导入 SSCL 场记板 XML 文件启用自动重命名
  5. 勾选"生成 HTML 报告"（默认开启）
  6. 点击 "Start Copy" 开始备份


【输出文件】

  作业完成后，目标目录下会生成以下文件：

    {作业名}_log.xml       — XML 日志（断点续传依据）
    {作业名}_report.html   — HTML DIT 报告（浏览器打开）


┌──────────────────────────────────────────────────────────────────────────────
│  微信推送设置（pushplus）
└──────────────────────────────────────────────────────────────────────────────

  拷贝任务结束（成功 / 校验失败 / 中断）后，可自动推送一条消息到微信。

  ■ 配置方法

    1. 点击主界面右上角「⚙ 设置」按钮
    2. 勾选「开启微信推送」
    3. 打开 pushplus 官网（https://www.pushplus.plus/），微信扫码登录，
       在「一对一推送」页面复制您的 Token
    4. 粘贴 Token，点击「测试推送」确认微信能收到消息
    5. 点击「保存」

  ■ 消息内容

    标题三态：DIT-拷贝成功 / DIT-拷贝失败 / DIT-拷贝中断
    正文：任务名称、拷贝文件数、视频文件数、非视频文件数、完成时间；
    失败任务附校验未通过文件数，中断任务附已验证进度。

  ■ 说明

    - Token 保存在本机用户目录（macOS 偏好设置 / Windows 注册表），
      重启或升级程序后无需重新输入
    - 推送经由 pushplus 服务转发，需电脑可访问互联网
    - 未开启推送或未填 Token 时，任务流程不受任何影响

  ■ 从 DMG 安装（推荐）

    1. 双击 DIT Offload.dmg 挂载磁盘映像

  ■ 首次启动提示"无法验证开发者"

    由于未经过 Apple 公证，首次启动时 macOS 会阻止运行。
    按以下步骤绕过（只需操作一次）：

    │ 方法 A（推荐）：
    │   右键（或 Ctrl+点击）DIT OFFLOADER.app →「打开」
    │   在弹出的对话框点击「打开」
    │
    │ 方法 B：
    │   系统设置 → 隐私与安全性 → 向下滚动到"安全性"
    │   → 找到"已阻止 DIT OFFLOADER.app" → 点击「仍要打开」

    之后再次启动无需重复此操作。


┌──────────────────────────────────────────────────────────────────────────────
│  FFmpeg 安装（强烈建议安装）
└──────────────────────────────────────────────────────────────────────────────

  FFmpeg 用于报告中的视频缩略图提取和元数据显示。
  未安装时程序仍可正常完成拷贝和校验，仅报告中视频预览不可用。

  ── Windows ──

  安装方式（任选一种）：

    1. winget（推荐，一键安装）：
       winget install Gyan.FFmpeg

    2. Scoop：
       scoop install ffmpeg

    3. Chocolatey：
       choco install ffmpeg

    4. 手动安装（离线 / 无管理员权限）：
       a) 从 https://www.gyan.dev/ffmpeg/builds/ 下载
          ffmpeg-release-essentials.zip
       b) 解压后将 bin 文件夹复制到 C:\ffmpeg\bin\
       c) 确保 C:\ffmpeg\bin\ 下存在 ffmpeg.exe 和 ffprobe.exe

  安装后程序会自动检测，无需配置环境变量。

  ── macOS ──

  ■ 安装 Homebrew（如尚未安装）：
    打开终端（启动台 → 其他 → 终端），粘贴以下命令并回车：

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    安装过程中按提示输入密码并按回车确认。

  ■ 安装 FFmpeg：
    终端中运行：

    brew install ffmpeg

    安装完成后终端输入 ffmpeg -version 看到版本信息即成功。

  DIT OFFLOADER 启动时自动检测 /opt/homebrew/bin/ 和 /usr/local/bin/，
  无需额外配置。

  版本：Beta 1.0.4
  日期：2026-09-09

  1.0.4 变更（相对 1.0.3）：

  ● 微信推送（新增）
    - 拷贝任务结束自动通过 pushplus 推送微信：任务名、拷贝文件数、
      视频/非视频文件数、完成时间；失败附校验未通过数，中断单列标题
    - 右上角「⚙ 设置」：推送开关 + Token 配置 + 测试推送，
      Token 持久化保存（用户目录，重装升级不丢失）

  ● 断点续传可靠性（重要修复）
    - 拷贝中途拔出存储卡时，任务改判为「中断」(Aborted) 并写明原因，
      不再误标为「完成」——旧版会把拔卡中断的作业写成 Completed，
      导致再次插入卡后只提示「追加拷贝」、整单重拷、断点续传失效
    - 续传判定改为按「是否仍有未完成文件」而非整体状态：只要日志里
      还有失败/待办文件，就会提示继续未完成任务
    - 续传时对上次已完成的文件不直接信任，而是重新读取目标盘校验：
      若目标盘发生静默损坏/文件缺失，会自动重拷并再次校验，日志中
      过期的目标路径也会一并修正
    - 重校验失败后的重拷一律按「保留」处理（不受"跳过已存在"策略影响）：
      确保该源文件在目标盘上一定有副本；同名位置被占用时追加 -1，
      绝不覆盖已有文件；该 -1 文件名与路径会如实显示在 HTML 报告中
    - 续传任务仅在全部文件校验通过后才生成 HTML 报告（有失败则不出
      报告，避免把未确认可靠的备份记录成"合格"）
    - 仅当源盘确实不可访问时才判中断；单个文件被外部删除仍按单文件
      失败处理，不影响其余文件

  ● 左侧驱动器面板
    - 隐藏 Time Machine 备份挂载（/Volumes/.timemachine 等）、网络卷
      （SMB/NFS/AFP/WebDAV）及外置系统盘自动挂载的 Preboot/Recovery/
      VM/Update 卷，只显示真实可用的数据卷
    - 卷按钮显示真实卷名（如 "CANON EOS (disk4s2)"），不再是裸设备名
    - 每 4 秒自动检测热插拔（后台枚举，不卡界面），无需手动点刷新

  ● 拷贝引擎（修复读卡器偶发报错）
    - 源 hash 改为拷贝数据流中顺带计算，源盘只读一次；移除独立的
      预读线程——旧版最多 5 路并发读同一张卡，是廉价 USB 读卡器
      偶发 Input/output error 的主因
    - 读侧瞬时错误（EIO/EBUSY 等）自动指数退避重试并从断点续写
    - 拷贝失败自动清理半截目标文件；断点续传自动清理上次残留，
      完整拷贝拿回原始文件名
    - 拷贝完成后校验字节数与源一致
    - 多个源含同名文件时（KEEP 策略）按 -1/-2 共存，消除并发写
      同一目标文件的竞态

  ● 校验与日志
    - 开启双校验时源 hash 缺失直接判失败，不再静默按通过处理
    - 作业启动前预检目标盘剩余空间，不足则拒绝启动
    - XML 日志按状态分级落盘：verified/failed/skipped 即时写出，
      中间状态（copying/verifying）按 200ms 合并，大幅降低写放大
    - 日志字段容错：size 等属性被外部改写为非数字时不再导致解析失败、
      整单无法启动（坏字段按 0 处理，日志照常用于断点续传）

  ● 界面
    - 单文件失败不再逐个弹模态框，作业结束合并为一个汇总弹窗
    - 报告生成改为读取目标盘上的拷贝产物（ffprobe/抽帧），
      拷完即可拔卡，报告仍能完整生成
    - 左侧文件浏览器：存储卡格式化/拔插后点「刷新」立即显示
      新目录内容（重建文件模型，不再残留格式化前的目录树）；
      卷插拔后自动同步文件树浏览位置

  ● 任务队列（Job Queue）
    - 按目标盘调度：同一目标盘的任务自动排队串行执行，不同目标盘
      的任务并发执行——支持双重备份（同一张卡同时拷往两块盘，
      互不等待）；作业运行期间可继续配置并添加新任务
    - 任务名自动防重名：追加拷贝到同一目录时，若与已有任务重名
      （或同名任务正在排队/执行），任务名自动改为 J-1 / J-2…，
      XML 日志与 HTML 报告随任务名一起版本化；断点续传始终沿用
      被续传日志的任务名
    - 任务参数在点击开始时快照：运行中修改源列表/重命名设置只
      影响之后提交的任务，不影响已在执行的任务
    - 修复同名任务互相覆盖内部状态导致旧任务进度条停止更新的问题
    - 右侧面板新增「🗑 清空已完成」按钮，一键移除所有已结束的任务卡片
    - 已完成（✅ Done）的任务卡片点击左键直接在访达/资源管理器中
      打开目标目录

  ● 追加拷贝防覆盖
    - 同一目标目录用同一任务名追加拷贝时，XML 日志与 HTML 报告
      自动追加 -1/-2 后缀（J → J-1 → J-2），不再覆盖上一次的
      DIT 报告（worker 侧仍保留同名兜底检查）
